# 第一天任务 4：Rokae `main.cpp` 代码讲解

## 1. 文件职责与安全等级

文件位置：

```text
teleop_ws/src/rokae_rt/src/main.cpp
```

这是整个项目中风险最高的文件，因为它直接调用 Rokae SDK 控制物理机器人。节点名是：

```text
/rt_robot_control_node
```

它订阅 `/sent_joints`，把 7 个关节目标交给实时控制器。

> 仅启动该节点就可能让机器人运动，不需要等到按下 `c`。

## 2. 构造函数的执行顺序

创建节点对象时，构造函数会立即依次执行以下操作。

### 2.1 连接机器人

代码写死了两个地址：

```cpp
std::string robot_ip = "192.168.0.160";
std::string local_ip = "192.168.0.100";
robot_.connectToRobot(robot_ip, local_ip);
```

因此控制电脑对应网卡必须具有 `192.168.0.100/24` 地址，并且能连通 `192.168.0.160`。

### 2.2 切换模式并上电

```cpp
robot_.setOperateMode(OperateMode::automatic, ec);
robot_.setMotionControlMode(MotionControlMode::RtCommand, ec);
robot_.setPowerState(true, ec);
```

含义是切换自动运行模式、启用实时指令模式并上电。代码虽然传入了 `error_code`，但没有在每一步之后系统检查并处理错误，这是运行时需要额外关注日志和示教器状态的原因。

### 2.3 创建 `/sent_joints` 订阅

该节点使用深度为 1 的可靠 QoS 订阅：

```text
/sent_joints
```

回调函数是 `jointPositionCallback()`。

### 2.4 自动移动至全零位

构造函数随后执行：

```cpp
motion_controller_->MoveJ(0.5, robot_.jointPos(ec), zero_pos);
```

其中：

```cpp
zero_pos = {0, 0, 0, 0, 0, 0, 0};
```

这意味着节点启动后会从当前关节位置移动到七关节全零位置。必须在运行前确认：

- 全零位对当前安装方向是否安全。
- 回零路径是否碰到桌面、相机、末端工具或人员。
- `0.5` 在当前 SDK 接口中代表的速度含义。
- 示教器限速与硬件急停是否有效。

## 3. `jointPositionCallback()`：接收目标

回调只接受长度恰好为 7 的消息：

```cpp
if (msg->data.size() == 7)
```

合法目标会被复制到 `std::array<double, 7>`，然后放入 `joint_queue_`。

队列最大长度是 100。满时先删除最旧的一条，再加入新目标。这能限制内存增长，但也意味着控制延迟过大时会丢弃旧目标。

代码还检查相邻消息时间间隔：大于 1.5 ms 时打印警告。这说明下游实时命令的预期频率大约在 1 kHz 量级，而不是手套的 50 Hz。

## 4. 键盘回调

程序另开线程读取终端按键：

| 按键 | 调用 | 作用 |
| --- | --- | --- |
| `c` | `followed_loop(jointPosition)` | 启动关节位置实时控制 |
| `v` | `followed_loop(jointImpedance)` | 启动关节阻抗实时控制 |
| `q` | `rclcpp::shutdown()` | 请求退出节点 |

首次真机测试不建议使用 `v`。阻抗模式中代码设置的刚度为：

```text
[500, 500, 500, 500, 50, 50, 50]
```

这些参数必须由熟悉机器人动力学和安全设置的人员确认。

## 5. `followed_loop()`：开始实时跟随

该函数只允许控制循环启动一次。

### 5.1 选择初始目标

如果队列有目标，使用最新目标；否则使用全零位：

```cpp
target_pos = joint_queue_.empty() ? zero_pos : joint_queue_.back();
```

然后再次执行一次 `MoveJ` 到该目标。这是第二个可能产生明显运动的位置。

### 5.2 设置控制模式

- `c` 使用 `jointPosition`。
- `v` 使用 `jointImpedance`，并设置关节阻抗。

### 5.3 注册并启动实时回调

程序把 `rokae_callback()` 注册给 SDK，然后在独立线程调用阻塞式 `startLoop(true)`。从此 SDK 会持续获取下一帧关节命令。

## 6. `rokae_callback()`：每个实时周期发什么

回调逻辑可以简化为：

```text
控制尚未准备好
  └─ 返回机器人当前关节角，尽量保持当前位置

控制已准备好且队列有新命令
  └─ 返回队首的新关节目标，并保存为 last_valid_command

控制已准备好但没有新命令
  └─ 重复 last_valid_command
```

这意味着上游 Topic 暂时中断后，程序倾向于保持最后一次目标，而不是自动退出实时模式。

需要注意：代码没有看到明确的“消息超过多少毫秒未更新则停机”的看门狗。因此通信中断后的安全行为不能只依赖这份程序。

## 7. 析构和退出

析构函数尝试：

1. 停止实时循环。
2. 等待控制线程退出。
3. 关闭机器人电源。
4. 将运动控制模式切换到 `Idle`。

但代码只在 `control_thread_` 可 `join` 时，才会进入包含键盘线程 `join` 的分支。实际退出行为应在不上真机或安全条件下预先验证，不能把 `q` 当作硬件急停的替代品。

## 8. 当前代码中值得记录的风险点

### 风险 1：启动即自动上电并回零

这是最重要的风险。不要在不了解现场状态时运行节点。

### 风险 2：碰撞阈值调用被注释

代码声明了力矩阈值，但 `setCollisionBehaviour(...)` 被注释，不能假设程序已经配置碰撞保护。

### 风险 3：没有明显的指令超时停机

上游停止发布后，实时回调会继续使用最后一次有效命令。

### 风险 4：IP、零位和参数写死

机器人 IP、电脑 IP、零关节姿态和阻抗参数都写在代码中，不会自动适配另一台机器人或不同安装方式。

### 风险 5：软件退出不等于急停

进程可能受线程、SDK 或通信状态影响。真正危险时应使用经过确认的硬件急停。

## 9. 阅读后应能回答的问题

1. 谁真正连接机器人？——`rokae_rt_node`。
2. 它订阅什么？——`/sent_joints`，每条必须为 7 个数。
3. 启动节点后是否立即运动？——可能，会自动上电并 `MoveJ` 到全零位。
4. `c` 做什么？——启动关节位置实时跟随。
5. `v` 做什么？——启动关节阻抗实时跟随。
6. 没有新消息时怎么办？——保持最后一次有效目标。
7. `q` 是否等于急停？——不是，只是请求软件退出。
