# 机械臂项目四天入门计划

## 学习目标

在尽量不修改项目源码的前提下：

- 理解机械臂遥操作系统的 ROS 2 节点和 Topic 数据流。
- 在仿真中验证手套姿态到机械臂运动的控制过程。
- 掌握连接真机前必须完成的设备、网络和安全检查。
- 在有人监护且可以随时急停的条件下，完成低速、小幅度的真机运动。

> **安全提示：** 未确认机械臂零位、回零路径、急停方法和安全限速之前，不要启动 `rokae_rt_node`。该节点启动后会连接机器人、切换控制模式、上电，并执行回零运动。

## 第一天：理解 ROS 2 和项目控制链路

### 任务

1. 熟悉常用 ROS 2 节点和 Topic 命令。
2. 画出项目的 Topic 数据流。
3. 阅读 `arm_tele_real.py`。
4. 阅读 `main.cpp` 的构造函数、关节目标回调和键盘回调。

### 需要掌握的命令

```bash
ros2 node list
ros2 topic list
ros2 topic info /quat_data
ros2 topic echo /quat_data
ros2 topic hz /quat_data
ros2 topic echo /rokae_control_joints
ros2 topic echo /sent_joints
ros2 topic hz /sent_joints
```

### 需要理解的数据流

```text
WiseGlove
  └─ /quat_data
       └─ arm_tele_real（逆运动学）
            └─ /rokae_control_joints
                 └─ mpc_interpolation（轨迹平滑）
                      └─ /sent_joints
                           └─ rokae_rt_node
                                └─ Rokae 真机
```

### 重点阅读

- `teleop_ws/src/arm_tele_mujo/arm_tele_mujo/arm_tele_real.py`
  - `quat_callback()` 如何接收姿态数据。
  - `ori_inv()` 如何求解七个关节角。
  - 逆运动学失败时如何使用上一次有效关节角。
  - `/rokae_control_joints` 的发布逻辑。
- `teleop_ws/src/rokae_rt/src/main.cpp`
  - 构造函数如何连接机器人、切换模式和上电。
  - `jointPositionCallback()` 如何接收 `/sent_joints`。
  - `followed_loop()` 如何启动实时控制。
  - 键盘按键 `c`、`v`、`q` 分别执行什么操作。

### 当天完成标准

- 能够口头解释一条手套姿态数据如何最终变成真机关节运动。
- 知道 `/quat_data`、`/rokae_control_joints` 和 `/sent_joints` 分别包含什么。
- 知道哪些程序只计算目标，哪个程序会真正驱动机械臂。

## 第二天：在仿真中验证控制

### 任务

1. 启动 `arm_tele_sim`。
2. 启动手套节点并检查 `/quat_data`。
3. 验证仿真机械臂的运动方向和初始姿态。
4. 观察逆运动学失败、数据中断或姿态突变时的表现。

### 推荐启动顺序

终端一：

```bash
source /opt/ros/humble/setup.bash
cd ~/Imitation_learning-Proj/teleop_ws
source install/setup.bash
ros2 run arm_tele_mujo arm_tele_sim
```

终端二：

```bash
source /opt/ros/humble/setup.bash
cd ~/Imitation_learning-Proj/teleop_ws
source install/setup.bash
ros2 run wiseglove18 glove_data_pub
```

手套节点启动后，按 `a` 重置 IMU 姿态并开始发布 `/quat_data`。

终端三：

```bash
source /opt/ros/humble/setup.bash
cd ~/Imitation_learning-Proj/teleop_ws
source install/setup.bash
ros2 topic echo /quat_data
```

也可以检查发布频率：

```bash
ros2 topic hz /quat_data
```

### 仿真检查项目

- 手套静止时，仿真机械臂是否基本静止。
- 缓慢转动手腕、肘部和上臂时，对应机械臂运动方向是否正确。
- 是否存在突然跳到另一组关节解的现象。
- 是否出现 `No valid joint angles found` 等逆运动学警告。
- 停止手套数据后，机械臂是否保持最后姿态。
- 重新发布姿态数据时，机械臂是否出现明显跳变。

### 当天完成标准

- 仿真能够稳定启动和退出。
- `/quat_data` 数据稳定且发布频率基本正常。
- 能识别至少一次正常逆运动学和一次逆运动学失败的表现。
- 清楚手套动作与仿真机械臂动作的对应关系。

## 第三天：只检查真机环境，不驱动机械臂

### 任务

1. 检查 ROS 2 工作空间能否正常编译和加载。
2. 检查手套、力传感器和相机等设备端口。
3. 检查控制电脑和机械臂之间的网络。
4. 检查相关 ROS 2 Topic。
5. 请原项目负责人现场确认回零位置和急停流程。

> 本阶段不要启动 `rokae_rt_node`，也不要按任何实时控制启动键。

### 环境检查

```bash
source /opt/ros/humble/setup.bash
cd ~/Imitation_learning-Proj/teleop_ws
colcon build --symlink-install
source install/setup.bash
ros2 pkg list | grep -E 'arm_tele_mujo|mpc_interpolation|rokae_rt|wiseglove18'
```

### 手套设备检查

```bash
ls -l /dev/teleop/glove
sudo dmesg | grep ttyUSB
```

### 网络检查

项目代码中的默认地址为：

- 控制电脑：`192.168.0.100`
- Rokae 机械臂：`192.168.0.160`

检查命令：

```bash
ip addr
ping 192.168.0.160
```

如需给控制网卡配置地址，应先确认实际网卡名称，再执行：

```bash
sudo ip addr add 192.168.0.100/24 dev <实际网卡名称>
```

### 必须向原负责人确认的问题

- 七关节全零位是否是当前安装方式下的安全姿态。
- 从机械臂当前位置到全零位的路径是否会碰撞桌面、支架或末端工具。
- 示教器上的安全速度、碰撞检测和工作空间限制是否已经启用。
- 硬件急停、软件停止、故障复位和重新上电分别如何操作。
- 第一次真机测试应该采用关节位置模式还是阻抗模式。
- `MoveJ(0.5, ...)` 中 `0.5` 的确切含义和对应速度是否安全。

### 当天完成标准

- 工作空间能够正常加载，关键 ROS 2 包可以被找到。
- 设备路径和网络配置均已确认。
- 可以稳定连通 `192.168.0.160`。
- 已由熟悉设备的人员确认零位、回零路径和急停方法。

## 第四天：低速、小幅度真机测试

### 前置条件

- 原负责人或熟悉该机械臂的人员在场。
- 操作者能够随时按下硬件急停。
- 机械臂周围无人，运动区域内没有障碍物。
- 已确认零位和回零路径安全。
- 示教器已设置最低或足够低的安全速度。
- 仿真测试已经通过。

### 测试顺序

1. 先用示教器低速确认机械臂可以安全运动和停止。
2. 在不接入手套的情况下确认 ROS 2 节点及 Topic 状态。
3. 启动真机驱动并观察自动上电、回零过程。
4. 只使用关节位置模式进行第一次测试。
5. 先测试单关节或非常小的目标变化。
6. 确认停止命令和硬件急停有效。
7. 最后才接入手套遥操作。

### 驱动键盘控制

- `c`：启动关节位置实时控制。
- `v`：启动关节阻抗实时控制。首次测试不建议使用。
- `q`：退出控制程序并执行下电流程。

### 运动过程中持续观察

```bash
ros2 topic hz /quat_data
ros2 topic hz /rokae_control_joints
ros2 topic hz /sent_joints
```

同时观察：

- 是否出现关节突跳或明显振动。
- 手套静止时机械臂是否漂移。
- Topic 中断时机械臂是否安全保持位置。
- 逆运动学失败时是否保持上一次有效关节角。
- 实际运动方向是否与仿真一致。
- 驱动终端是否出现通信延迟、SDK 异常或控制周期警告。

出现异常时，应立即停止控制；如果软件停止无效，使用硬件急停。

### 当天完成标准

- 完成一次安全的低速回零。
- 完成一次单关节或小幅度运动。
- 验证软件退出和硬件急停流程。
- 在前述测试全部正常后，完成小幅度手套遥操作。

## 四天后的最低能力要求

完成以上学习后，应当能够：

- 解释项目中主要 ROS 2 节点的作用。
- 使用 ROS 2 命令检查节点、Topic、数据内容和发布频率。
- 区分仿真程序、逆运动学程序、轨迹插值程序和真机驱动程序。
- 在不修改源码的情况下启动仿真并定位常见问题。
- 按照确认过的安全流程进行低速、小幅度真机操作。
